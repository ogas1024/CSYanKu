## 题干

75. 为了缓解处理器与主存之间的速度差异，现代计算机系统同时引入了 TLB 和 Cache。下列关于 TLB 与 Cache 工作机制及缺失行为的叙述中，错误的是（ ）。

A. 进程切换时，由于虚拟地址空间发生改变，TLB 必须进行刷新而 Cache 通常无需刷新，因为不同进程的 Cache 内容可以共存

B. CPU 发出内存访问请求时，TLB 加速的是"地址翻译"，以虚拟页号作为查询依据；Cache 加速的是"数据读取"，通常以物理地址作为查询依据

C. 当 Cache 发生缺失时，必然由硬件自动完成数据块的替换与调入；而当 TLB 发生缺失时，必然会触发 TLB 缺失异常，引出操作系统内核中的异常处理程序来手动填充表项

D. 在一次取数操作中，完全可能出现"TLB 缺失，但由于页表项和目标数据均在 Cache 中命中，最终硬件访问主存的次数为 0 次"的理想情况

> [!note]- 原题截图
> ![[relax1000CO 03 存储系统 选择 075.webp]]

> [!success]- 答案与解析
> **答案：** C
>
> **解析：** A 正确：Cache 的查询 Key 是物理地址，而物理地址在内存中是全局唯一的，因此进程切换时无需刷新 Cache。但是，TLB 的查询 Key 是虚拟地址，不同进程中相同的虚拟地址会映射到完全不同的物理地址上。如果不刷新 TLB，新进程就会错误地使用旧进程的地址翻译结果。
>
> B 正确：这一项对比了二者的定位与寻址方式。TLB 的核心目的是解决"每次地址翻译都要访问主存页表的开销"，它的查询 Key 是虚拟页号，输出结果是物理页号。而 Cache 的核心目的是解决"CPU 与主存速度差"，它的缓存对象是主存中的数据或指令块，查询 Key 则是物理地址。简单来说：TLB 加速"找地址"，Cache 加速"取数据"。
>
> C 错误：Cache 缺失确实对软件完全透明，永远由硬件自动处理并从下级存储取数据块填入 Cache。但 TLB 缺失的处理方式视计算机架构而定：① x86 或 ARM 等架构中，TLB 是由硬件管理的，MMU 的内部硬件会自动遍历内存页表并填入 TLB，无需操作系统介入。② MIPS 等软件管理 TLB 的架构中，TLB 缺失才会触发异常，由操作系统的处理程序填入。
>
> D 正确：这一项考查了命中的组合情况。TLB 缺失仅仅意味着"快表里没有缓存这个映射"，但只要该页面有效（未发生缺页），数据就存在于主存中，也就有可能被缓存到了 Cache 中。当 TLB 缺失时，硬件会去查页表。如果代表该映射关系的页表项刚好在 Cache 中命中，且翻译出物理地址后，目标数据也刚好在 Cache 中命中，那么整个取数过程的数据全部是从 Cache 这个高速器件里拿到的，实际去读写主存（DRAM）的次数依然为 0 次。
