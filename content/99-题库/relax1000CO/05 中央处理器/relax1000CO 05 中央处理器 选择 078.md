## 题干

78. 在采用"取指、译码/取数、执行、访存、写回"5 段流水线的 RISC 处理器中，处理器使用数据转发（旁路）机制处理数据冒险，但对于 Load-use 冒险，硬件无法完全消除阻塞，必须插入 1 个气泡才能解决。现有一段 C 语言程序编译生成的汇编代码序列如下（R1~R9 为寄存器编号）：

```
I1: lw  R1,0(R2)   //R1 <- M[R2 + 0]
I2: add R3, R1, R4 //R3=R1+R4
I3: sub R5,R6,R7   //R5=R6-R7
I4: or  R8, R1, R9 //R8 = R1 | R9
```

编译器对上述指令序列进行指令重排优化，在保证程序逻辑正确的前提下，能够消除流水线阻塞的指令执行顺序是（　）。

A．I1, I4, I2, I3　　　　B．I1, I4, I3, I2　　　　C．I1, I3, I2, I4　　　　D．I3, I1, I2, I4

> [!note]- 原题截图
> ![[relax1000CO 05 中央处理器 选择 078.webp]]

> [!success]- 答案与解析
> **答案：** C
>
> **解析：** 首先对原始指令序列分析：I1 是 lw 指令，目标寄存器是 R1；I2 是 add 指令，源操作数包含 R1。在 5 段流水线中，lw 指令的数据在 MEM 段结束时才能从数据 Cache 中读出，而 add 指令需要在 EX 段开始时使用数据；时间上，I2 进入 EX 段时 I1 刚进入 MEM 段，数据尚未读出，即使有转发路径也无法转发，因此 I1 和 I2 之间发生了 Load-use 冒险。原始执行代价：顺序为 I1→stall→I2→I3→I4，必须插入 1 个气泡。
>
> 优化思路：要消除这个 Load-use 气泡，需要在 I1 和 I2 之间插入一条与它们都不相关的指令，利用这条指令来"填充"那个原本需要阻塞的时间片。需要检查每种重排顺序是否满足两个条件：①逻辑正确性——不能破坏原有的数据依赖关系（如写后读、写后写）；②冒险消除——lw R1 和使用 R1 的指令之间至少隔开一条指令。
>
> A 选项（I1,I4,I2,I3）：将 I4 提到 I2 之前，但 I4（or R8,R1,R9）也使用了 R1，仍需 1 个 stall，排除。
> B 选项（I1,I4,I3,I2）：同上，I4 紧跟 I1 仍使用 R1，仍需 stall，排除。
> C 选项（I1,I3,I2,I4）：将 I3 移到 I1 和 I2 之间，I3（sub R5,R6,R7）使用 R6、R7，写入 R5，与 I1（R1,R2）和 I2（R3,R1,R4）没有任何寄存器冲突，完全独立。流水线时序：I1（lw，在 MEM 段产出 R1）→I3（sub，无关指令，正常执行，占用了 lw 之后的那个周期）→I2（add，需要 R1）。当 I2 准备进入 EX 段时，I3 在 EX 段，I1 已经进入 WB 段（或 MEM 段刚结束），此时 R1 数据已经准备好，通过 MEM/WB 流水寄存器向 ALU 入口转发，Load-Use 阻塞被成功消除，正确。
> D 选项（I3,I1,I2,I4）：Load-use 冒险依然存在（I1 与 I2 之间未插入任何指令），产生 1 个阻塞。
>
> 故本题选 C。
