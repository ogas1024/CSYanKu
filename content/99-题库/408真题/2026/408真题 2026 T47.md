## 题干

47. （本题 9 分）人工智能（AI）是引领未来的战略性技术，其发展高度依赖强大的算力供给，通过网络互联分散的算力中心，可以充分聚合算力资源，满足人工智能对大规模算力的需求，支撑人工智能国家发展战略。某算力调度交易平台聚合各地的算力中心的算力，向用户提供算力服务的示意场景如题 47 图所示。算力用户 C 向平台申请算力服务，平台通过优化调度各算力中心算力，向 C 授权使用算力中心 $i$ 的算力，$S_i$ 为算力中心 $i$ 的负载均衡服务器，用于接收算力用户的计算任务描述数据文件，并向算力中心 $i$ 内部分派计算任务。为确保可靠传输，假设 C 建立一条 TCP 连接向服务器 $S_i$ 上传一个总长度为 2000 B 的计算任务描述数据文件，拥塞窗口初始阈值为 8 MSS，MSS = 500 B，$S_i$ 对收到的每个 TCP 段进行确认，且确认段不封装数据，接收窗口 rwnd 始终为 1000 B，RTT = 5 ms。C 建立连接时选择的初始序号为 1000，$S_i$ 选择的初始序号为 2000，SYN、ACK、FIN 为标志位，seq 为序号，ack_seq 为确认序号。在整个文件传输过程中未出现任何重传或报文段丢失。

![[408真题 2026 T47-fig1.webp]]

题 47 图

请回答下列问题。

（1）C 与 $S_i$ 建立 TCP 连接过程需要几次握手？C 收到的 SYN = 1、ACK = 1 的 TCP 段的确认序号（ack_seq）是多少？（2 分）

（2）当 C 接收到 $S_i$ 发送的“ACK = 1，seq = 2001，ack_seq = 2001，rwnd = 1000”确认段后，C 的拥塞窗口增加到多少？C 的发送窗口设置为多少？（2 分）

（3）C 与 $S_i$ 释放 TCP 连接过程需要几次挥手？C 收到的最后一个 TCP 报文段的序号（seq）、确认序号（ack_seq）、FIN 的值分别是多少？（4 分）

（4）若忽略报文段传输时延，且时间从 C 请求建立 TCP 连接时刻算起，则 C 确认 $S_i$ 已成功接收到文件的时间是多少？（1 分）

> [!success]- 答案与解析
> **官方答案要点：**
>
> （1）建立 TCP 连接过程需要 3 次握手。C 收到的 SYN=1、ACK=1 的 TCP 段的确认序号 ack_seq=1001。
>
> （2）拥塞窗口增加到 3MSS=1500 B。发送窗口设置为 2MSS=1000 B。
>
> （3）释放 TCP 连接过程需要 4 次挥手。C 收到的最后一个 TCP 段的 seq=2001、ack_seq=3002、FIN=1。
>
> （4）C 确认 $S_i$ 已成功接收到文件的时间是 $4\times 5\ \text{ms}=20\ \text{ms}$。
>
> **解析（据官方答案整理推导）：**
>
> 先理清序号：C 的初始序号为 1000，SYN 消耗 1 个序号，所以文件数据从序号 1001 开始，2000 B 占用 1001～3000，按 MSS = 500 B 分成 4 个报文段：段 1（1001～1500）、段 2（1501～2000）、段 3（2001～2500）、段 4（2501～3000）。$S_i$ 的初始序号为 2000，其 SYN 同样消耗 1 个序号，此后 $S_i$ 的确认段不带数据，seq 一直是 2001。
>
> （1）TCP 建立连接需要 3 次握手：C 发 SYN（seq=1000）；$S_i$ 回 SYN+ACK（seq=2000，ack_seq=1001）；C 再发 ACK。C 收到的 SYN=1、ACK=1 段是第二次握手，它确认 C 的 SYN 占用的序号 1000，期望下一个字节序号为 1001，故 ack_seq = 1001。
>
> （2）初始拥塞窗口 cwnd = 1 MSS，阈值 ssthresh = 8 MSS，处于慢开始阶段，每收到一个对新数据的确认，cwnd 增加 1 MSS。
>
> - 握手完成后 C 发出段 1。收到确认 ack_seq=1501 后，cwnd = 2 MSS = 1000 B，发送窗口 = min(cwnd, rwnd) = min(1000, 1000) = 1000 B，发出段 2、段 3。
> - 题中确认段 ack_seq = 2001 确认的是段 2，收到后 cwnd 再加 1 MSS，增加到 3 MSS = 1500 B。
> - 发送窗口取拥塞窗口和接收窗口的较小者：min(1500 B, 1000 B) = 1000 B = 2 MSS，此时受接收窗口限制。
>
> （3）TCP 释放连接需要 4 次挥手：
>
> 1. C 发 FIN：数据最后一个字节序号为 3000，故 FIN 段 seq = 3001，FIN 本身消耗 1 个序号。
> 2. $S_i$ 回 ACK：seq = 2001，ack_seq = 3002。
> 3. $S_i$ 发 FIN：仍未发送过数据，seq = 2001，ack_seq = 3002，FIN = 1。
> 4. C 回最后的 ACK。
>
> C 收到的最后一个报文段是第 3 次挥手的 FIN 段：seq = 2001，ack_seq = 3002，FIN = 1。
>
> （4）忽略传输时延，每个“发出—收到确认”的往返都是 1 个 RTT = 5 ms：
>
> - 0 ms：C 发 SYN。
> - 5 ms：C 收到 SYN+ACK，发出第三次握手的 ACK 和段 1。
> - 10 ms：C 收到 ack_seq=1501，cwnd = 2 MSS，发送窗口 1000 B，发出段 2、段 3。
> - 15 ms：C 收到 ack_seq=2001（cwnd = 3 MSS，发送窗口仍为 1000 B，可发到 3000，于是发出段 4）和 ack_seq=2501。
> - 20 ms：C 收到 ack_seq=3001，说明 1001～3000 全部被正确接收，C 确认 $S_i$ 已成功接收文件。
>
> 共经历 4 个 RTT（握手 1 个 + 数据传输 3 个），时间为 $4\times 5\ \text{ms} = 20\ \text{ms}$。
