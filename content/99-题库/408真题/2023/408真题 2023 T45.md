## 题干

45. （7分）现要求学生使用 swap 指令和布尔型变量 lock 实现临界区互斥。

lock 为线程间共享的变量。lock 的值为 TRUE 时线程不能进入临界区，为 FALSE 时线程能进入临界区。某同学编写的实现临界区互斥的伪代码如下：

```c
bool lock = FALSE; // 共享变量
……
bool key = TRUE;
if (key == TRUE)
    swap key, lock; // 交换 key 和 lock 的值
临界区；
lock = TRUE; // 退出区
……
```

（a）

（1）图（a）的伪代码中哪些语句存在错误？将其改为正确的语句（不增加语句条数）。

（2）图（b）给出了交换两个变量值的函数 newSwap() 的代码，是否可以用函数调用语句 `newSwap(&key,&lock)` 代替指令 `swap key,lock`，以实现临界区的互斥？为什么？

```c
void newSwap(bool *a, bool *b) {
    bool temp = *a;
    *a = *b;
    *b = temp;
}
```

（b）

> [!note]- 原题截图
> ![[408真题 2023 T45.webp]]

> [!success]- 答案与解析
> **解析：**
>
> (1) ① 进入区中的语句 “if(key == TRUE) swap key, lock;” 存在错误，修改为 “while(key == TRUE) swap key, lock;”。因为 if 语言无论判断结果如何，都会继续向下执行。因为对于实现临界区互斥访问，应该使用循环来等待 lock 变量为 FALSE 的时候再进入临界区，以确保在 lock 为 TRUE 时一直等待，直到 lock 为 FALSE 才能进入临界区。② 退出区中语句 “lock = TRUE” 存在错误，修改为 “lock = FALSE”。因为 lock 为 TRUE 代表上锁了，退出区需要将 lock 解锁，让其他的线程可以访问临界区。
>
> (2) 否。不能使用函数 “newSwap(&key, &lock)” 替代指令 “swap key, lock”。因为 newSwap 为函数调用，其执行不具备原子性（swap 是硬件指令，由硬件保证原子性），在调用函数 newSwap 执行时，传递给形参 b 的是引用 lock，而在执行 newSwap 的过程中，会修改 lock 的值。多个线程可以并发执行函数 newSwap，导致 lock 的值受到多个线程的影响，可能导致多个并发执行的线程同时进入临界区，无法正确实现临界区的互斥。
>
> 【点评】冷门考点。此题考查通过硬件同步机制实现临界区互斥。从知识点的角度来说，如果学过这个考点，其实很简单。如果考前忽略了这个考点的学习，则容易出错。由于信号量实现进程同步互斥考查较多，另外两种通过软件和硬件机制实现临界区互斥的方法，可能容易被考生忽略。这里再次提醒各位考生，只要是408考试大纲中的内容，408都有可能考到，不能放弃某个考点不学。
