## 题干

27. 进程 $P_0$ 和 $P_1$ 的共享变量定义及其初值为：

```c
boolean flag[2];
int turn=0;
flag[0]=FALSE; flag[1]=FALSE;
```

若进程 $P_0$ 和 $P_1$ 访问临界资源的类 C 伪代码实现如下：

```c
void P0()  // 进程 P0
{
    while(TRUE)
    {
        flag[0]=TRUE; turn=1;
        while(flag[1]&&(turn==1));
        临界区;
        flag[0]=FALSE;
    }
}

void P1()  // 进程 P1
{
    while(TRUE)
    {
        flag[1]=TRUE; turn=0;
        while(flag[0]&&(turn==0));
        临界区;
        flag[1]=FALSE;
    }
}
```

则并发执行进程 $P_0$ 和 $P_1$ 时产生的情形是（）。

A. 不能保证进程互斥进入临界区，会出现“饥饿”现象

B. 不能保证进程互斥进入临界区，不会出现“饥饿”现象

C. 能保证进程互斥进入临界区，会出现“饥饿”现象

D. 能保证进程互斥进入临界区，不会出现“饥饿”现象

> [!note]- 原题截图
> ![[408真题 2010 T27.webp]]

> [!success]- 答案与解析
> **答案：** D
>
> **解析：** 这道题的代码正是著名的 Peterson 算法（1981 年提出），是解决双进程互斥问题的经典软件实现。 $P_0$ 进入临界区的条件：!(flag[1] && turn == 1);  $P_1$ 进入临界区的条件：!(flag[0] && turn == 0)。
>
> ① 首先分析互斥性：假设  $P_0$ 已经进入临界区，说明此时 flag[1] == false 或者 turn != 1（即 turn == 0）。这里分 2 种情况讨论：
>
> ◇ 若 flag[1] == false，说明此时  $P_1$ 还没执行 flag[1] = true（还未申请进入临界区），或者此时  $P_1$ 已经退出了临界区。
>
> ◇ 若 turn == 0，此时  $P_0$ 还在临界区，所以 flag[0] == true。此时 while(flag[0] && turn == 0) 因循环条件成立而进入死循环，故  $P_1$ 无法进入临界区。
>
> 再假设  $P_{1}$ 已进入临界区，分析方法和上述完全一致。所以，可保证两个进程互斥进入临界区。 **②再分析是否会导致“饥饿”**：“饥饿”指某个进程永远无法获得临界区的访问权。每个进程在进入临界区前，都会主动将 turn 设置为对方进程的编号，这保证了两个进程都有平等的优先级。只要占用临界区的进程执行完毕，退出时会将自身的 flag 置为 false，此时等待进程的循环条件会立即解除，就可以进入临界区。等待时间是有限的，不会无限期等待。故不会导致“饥饿”。
>
> 【点评】常规题。本题考查 Peterson 算法的思想。
