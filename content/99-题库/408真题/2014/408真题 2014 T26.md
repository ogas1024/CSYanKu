## 题干

26. 一个进程的读磁盘操作完成后，操作系统针对该进程必做的是（）。

A. 修改进程状态为就绪态

B. 降低进程优先级

C. 给进程分配用户内存空间

D. 增加进程时间片大小

> [!note]- 原题截图
> ![[408真题 2014 T26.webp]]

> [!success]- 答案与解析
> **答案：** A
>
> **解析：** A 正确：进程发起读磁盘 I/O 操作后，会从运行态变为阻塞态，等待磁盘 I/O 完成。当磁盘操作完成后，硬件会发出中断，操作系统处理中断时，必须把这个等待 I/O 的进程状态修改为就绪态，等待 CPU 调度。
>
> B 选项：降低进程优先级不是必须操作。某些调度算法（例如，多级反馈队列）可能调整优先级，但这不是普遍要求。
>
> C 选项：读磁盘是把数据加载到已分配的缓冲区或内存，不需要额外分配用户内存空间。内存分配通常在进程创建时完成。
>
> D 选项：时间片调整取决于具体调度策略，不是 I/O 完成后的必做操作。
>
> 【拓展】①处于阻塞态的进程既缺少处理器资源，又缺少其他资源。而处于就绪态的进程只缺少处理器资源。②操作系统这门课程理论概念多，学起来感觉很抽象，看不见摸不着。408考生都是为了应试才学，大多只停留在概念阶段。建议考生尽量结合一些具体的例子学习，能加深理解、印象也更深刻。这里将进程读磁盘前后的完整操作拆解如下：
>
> (1) 首先需要明确，为什么进程发起磁盘 I/O 后要进入阻塞态？
>
> CPU 执行一条指令仅纳秒级（ $10^{-9}$s），而机械磁盘寻道、读写耗时毫秒级（ $10^{-3}$s），速度相差百万倍。如果进程发起读盘后不放弃 CPU，CPU 会原地空循环等待磁盘，造成处理器资源完全浪费。所以进程会主动让出 CPU。
>
> (2) 进程读磁盘前后的完整流程：
>
> ◇ 1. 进程处于运行态：正在 CPU 上执行代码，调用 read() 系统调用发起磁盘读请求。
>
> 2. 陷入内核态：执行 I/O 相关特权指令，向磁盘控制器下发读写命令。
>
> 3. 进程主动放弃 CPU，转为阻塞态。操作系统内核做两件事：(a) 将该进程 PCB（进程控制块）移入 I/O 等待队列，标记状态为阻塞；(b) 调用进程调度程序，从就绪队列挑选
>
> 另一个就绪进程占用CPU。
>
> 4. 磁盘硬件独立工作：磁盘控制器不依赖 CPU，自行完成磁头寻道、数据读取，全程 CPU 可以运行其他程序。
>
> 5. I/O 完成触发中断：磁盘读完数据后发送硬件中断，OS 中断处理程序把该进程从阻塞队列移出，并修改为就绪态，放回就绪队列等待调度。
>
> 【点评】难题。结合具体的实例考查进程的状态转换，类似的题是408考查的趋势。若平时涉猎不广，只背概念，做此类题就“摇摆不定”、不确定到底选哪个。
