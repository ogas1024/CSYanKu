## 题干

29. 在一个文件被用户进程首次打开的过程中，操作系统需要做的是（）。

A. 将文件内容读到内存中

B. 将文件控制块读到内存中

C. 修改文件控制块中的读写权限

D. 将文件的数据缓冲区首指针返回给用户进程

> [!note]- 原题截图
> ![[408真题 2014 T29.webp]]

> [!success]- 答案与解析
> **答案：** B
>
> **解析：** 因为此类题经常考，为了让考生对文件的打开过程有更全面的了解，这里先概要介绍文件打开的完整流程（★这个过程考生必须熟练掌握），再逐个分析各个选项。
>
> ▷①文件 open 打开操作完整流程如下：
>
> 1. 检索目录，定位 FCB:
>
> ◇ 根据传入的文件路径，逐层查找目录项，在外存找到目标文件对应的文件控制块 FCB （或 inode 索引节点）。
>
> 2. 读入 FCB 到内存：
>
> ◇ 把外存上存储文件元数据的 FCB 加载到内存，生成内存 FCB，这就是本题 B 选项对应的操作。FCB 保存文件名、文件大小、磁盘块地址、读写权限、创建 / 修改时间、链接计数等文件元数据信息。
>
> 3. 权限校验：
>
> 对比进程当前身份与 FCB 内读写权限，判断是否允许本次打开模式（只读 / 只写 / 读写）；若当前进程无打开文件的权限，则直接返回文件打开失败。
>
> 4. 创建进程私有打开文件表项：
>
> ◇  **在进程 PCB 的打开文件表中新建表项**，记录：指向内存 FCB 的指针、文件当前读写偏移量（初始为 0）、本次打开的访问模式（只读 / 可写等）。
>
> 5. 分配并返回文件描述符 fd:
>
> ◇ 将上一步在进程 PCB 的打开文件中，新建表项的下标（即：文件描述符 fd）返回给用户进程， **进程后续再次操作该文件（read / write / close 等）都通过 fd 进行**。文件描述符 fd 是进程私有打开文件表的数组下标。在 Linux 中，“一切皆文件”，进程所有 I/O 资源（普通文件、管道、socket、终端、设备等）全部统一用文件描述符 fd 标识。
>
> ▷② 再逐个分析各个选项：
>
> A 错误×: 首次打开文件时, 不需要立刻把整个文件内容读到内存, 只有后续进行 $\underset{\cdot}{读}\underset{\cdot}{写}\underset{\cdot}{操}\underset{\cdot}{作}$ (read 和 write 系统调用) 时才会按需加载文件数据。
>
> B 正确 ✓：文件控制块（FCB）存放着文件的元数据（文件名、位置、权限、大小等），文件首次打开时，操作系统必须先把外存上的 FCB 读入内存，才能获取文件的管理信息、完成合法性校验等打开流程。
>
> C 错误 ×：打开文件不会修改文件控制块的读写权限，权限是文件创建或专门修改权限时设置的，打开操作只会校验权限。修改权限需要单独系统调用 chmod()，open() 仅校验权限，不修改。D 错误 ×：打开文件会返回文件描述符 fd，不会直接把数据缓冲区首指针返回给进程，缓冲区由操作系统内核管理。
>
> 【点评】难题。文件的打开和读取等操作是408中的重难点，也是高频考点。2012年408第28题考查“read系统调用”、本题其实是考“open系统调用”，考生可结合竟成写的这两题的解析，对比学习。
