## 题干

46. （本题 9 分）

某进程的虚拟地址空间如下图所示，阴影部分为未占用区域。

![[408真题 2025 T46-fig1.webp]]

另现有 C 程序代码：

```c
char *ptr;

void main()
{
    int length;
    ptr = (char*)malloc(size of(char));
    scanf("%s", ptr);
    length = strlen(ptr);
    printf("length=%d\n", length);
    free(ptr);
}
```

请回答下列问题，并说明理由。

（1）上述程序执行时，PCB 位于哪个区域，执行 `scanf()` 等待键盘输入时，该进程处于什么状态？（3 分）

（2）`main()` 函数的代码位于哪个区域？其直接调用的哪些函数的功能需要通过执行驱动程序实现？（3 分）

（3）变量 `ptr` 被分配在哪个区域？若变量 `length` 没有被分配在寄存器中，则会被分配在哪个区域？`ptr` 指向的字符串位于哪个区域？（3 分）

> [!note]- 原题截图
> ![[408真题 2025 T46.webp]]

> [!warning]- 原题代码问题
> 题面代码中的 `size of(char)` 不是合法 C 表达式；即使按 `sizeof(char)` 理解，1B 缓冲区接收 `%s` 也可能越界。以下按题目考查的进程地址空间与 I/O 语义作答，不把这处排印与示例代码缺陷改写掉。

> [!success]- 答案与解析
> **解析：**
>
> （1）进程控制块位于内核区。该进程处于阻塞态。
>
> ①PCB（进程控制块）是操作系统内核为管理进程而维护的数据结构，存储进程ID、状态、优先级、寄存器上下文、内存映射等关键信息。由于PCB包含内核级敏感数据（例如：页表基址、内核栈指针等），且仅允许操作系统内核访问（用户态程序无权限操作），因此PCB必须位于内核区（虚拟地址空间的最高特权区域）。
>
> ② scanf() 是标准输入函数，需等待用户通过链盘输入数据。当进程执行 scanf() 时，因无法立即获得输入数据，会通过系统调用陷入内核，主动放弃 CPU 使用权。此时进程进入阻塞态（等待态），其特征是：进程暂停执行，PCB 被移入阻塞队列，等待 I/O 完成（键盘输入就绪）。阻塞态的进程不会被调度，直到事件（输入完成）触发唤醒。
>
> (2) main() 函数的代码位于只读代码段。scanf() 和 printf() 的功能需要通过执行驱动程序实现。main 函数的代码位于只读代码段（代码段存储程序指令，通常设为只读以避免指令被意外修改）；它直接调用的 scanf() 和 printf() 需执行驱动程序，因为这两个函数涉及与硬件（键盘、显示器）的交互，而硬件的具体操作需通过操作系统内核中的驱动程序（硬件与操作系统的接口）来完成实际控制。
>
> (3) ptr 分配在可读写数据段中。length 会被分配在用户栈中。ptr 指向的字符串位于运行时堆中。
>
> ① 题目中 ptr 的定义为 char* ptr；(位于 main() 函数外部，属于全局变量)，且题目未提及分配在寄存器中。根据虚拟地址空间功能划分：可读写数据段（.data/.bss 段）专门用于存储全局变量和静态变量（非局部变量），这类变量的生命周期与程序运行周期一致，且允许在运行中修改值（例如，ptr = (char*)malloc(...) 对指针值的修改)；用户栈仅用于存储函数内的局部变量（例如，main() 内定义的临时变量），而 ptr 是全局变量，不属于局部变量范畴，因此不能存于用户栈。综上，ptr 作为全局指针变量，未分配至寄存器时，被分配在可读写数据区。
>
> ② length 是 main() 函数内定义的局部整型变量 (int length)，且题目明确 “未被分配在寄存器中”。与 ptr 同理，用户程序的局部变量（非寄存器分配）均存储于用户栈，故 length 被分配在用户栈。
>
> ③ptr 指向的内存由malloc(sizeof(char))动态分配。根据虚拟地址空间功能划分，malloc是C语言中用于动态内存分配的函数，其分配的内存来自运行时堆（运行时堆专门用于存储程序运行过程中动态申请的内存，例如：malloc/new分配的空间），需手动通过free释放，因此ptr指向的字符串位于运行时堆。
>
> 【点评】冷门考点。结合具体的C语言代码，考查进程内存空间布局。此考点在此前的408真题中从未考过，出题角度比较出其不意。但本题即使不会，其实“连蒙带猜”也能拿到一些分。本题改编自陈海波、夏虞斌等编著的《现代操作系统原理与实现》（机械工业出版社）第78页“5.1.2进程内存空间布局”小节。这本书作者阵容强大，由国内顶尖高校知名教授联合编写，理论结合实际，建议学有余力的考生可看下该教材。
