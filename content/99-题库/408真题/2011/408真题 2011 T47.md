## 题干

47. （9 分）某主机的 MAC 地址为 `00-15-C5-C1-5E-28`，IP 地址为 `10.2.128.100`（私有地址）。

题 47-a 图是网络拓扑，题 47-b 图是该主机进行 Web 请求的 $1$ 个以太网数据帧前 $80\ \mathrm{B}$ 的十六进制及 ASCII 码内容。

请参考图中的数据回答以下问题。

![[408真题 2011 T47-fig3.webp|500]]

题 47-b 图　以太网数据帧（前 $80\ \mathrm{B}$）

（1）Web 服务器的 IP 地址是什么？该主机的默认网关的 MAC 地址是什么？
（2）该主机在构造题 47-b 图的数据帧时，使用什么协议确定目的 MAC 地址？封装该协议请求报文的以太网帧的目的 MAC 地址是什么？
（3）假设 HTTP/1.1 协议以持续的非流水线方式工作，一次请求—响应时间为 RTT，`rfc.html` 页面引用了 $5$ 个 JPEG 小图像，则从发出题 47-b 图中的 Web 请求开始到浏览器收到全部内容为止，需要多少个 RTT？
（4）该帧所封装的 IP 分组经过路由器 R 转发时，需修改 IP 分组头中的哪些字段？

注：以太网数据帧结构和 IP 分组头结构分别如题 47-c 图、题 47-d 图所示。

> **解析：**
>
> (1) ① 因为题目给出的是该主机进行 Web 请求的以太网帧，所以 Web 服务器的 IP 地址就是此以太网帧中 IP 分组目的地址。根据图 (c) 以太网帧结构：目的 MAC 地址 (6B) + 源 MAC 地址 (6B) + 类型 (2B) + 数据 (IP 分组)。所以 IP 分组从第  $6+6+2=14$ 字节开始。根据图 (d) IP 分组头结构，目的 IP 地址之前有 16 字节。所以目的 IP 地址是从第  $14+16=30$ 字节开始的连续 4 个字节，即 40 aa 62 20H，转化成点分十进制为 64.170.98.32。即 Web 服务器的 IP 地址的 IP 地址是 64.170.98.32。
>
> ②主机发送跨网段 IP 分组时，以太网帧的目的 MAC 地址是默认网关的 MAC 地址。根据图 (c) 以太网帧结构，该帧的目的 MAC 地址是前 6 字节，故该主机的默认网关的 MAC 地址是 00-21-27-21-51-ee。
>
> 【提示】题目给出的以太网帧前80B的格式叫hexdump格式，是网络抓包、逆向工程、底层调试中最常用的数据查看方式。如下表所示，hexdump格式由3部分组成：
>
> ◇  **偏移地址 (Offset)**：通常用4位或8位的十六进制数表示。标记该行数据在整个文件/数据块中的起始字节位置。每一行默认16字节。
>
> ◇  **十六进制数据区**：每行固定16个字节，每字节用2位十六进制表示，中间用空格分隔；常按8字节分两组，便于阅读。
>
> ◇  **ASCII 字符区**：十六进制数据区的每个字节，直接对应 ASCII 区同一位置的字符，不可打印字符用点替代。作用是快速识别数据中的文本内容，方便定位关键信息。

> (2) 主机使用 ARP 协议（地址解析协议）确定目的 MAC 地址。ARP 请求是广播报文，因此封装 ARP 协议请求报文的以太网帧目的 MAC 地址是 FF-FF-FF-FF-FF-FF。
>
> (3) 题目中说明 HTTP/1.1 协议以非流水线的持续连接方式工作。
>
> ◇ 持续连接指在同一个 TCP 连接上，可以进行多次 HTTP 请求与响应，传输多个对象，TCP 连接不会在每次请求响应后立即释放。
>
> 非流水线指客户端仅在收到前一个 HTTP 响应之后，才能发送下一个 HTTP 请求。由图 (b) 图中 “tml HTTP” 可知，主机当前请求的是 rfc.html 文档，需要一个 RTT。rfc.html 引用了 5 个 JPEG 小图像，请求每个 JPEG 均需要一个 RTT。所以，浏览器总共需要  $1 + 5 = 6$ 个 RTT 才能接收到全部内容。
>
> 【提示】①本题的易错点是：发出图(b)所示的Web请求时，TCP连接已经建立，不需要考虑TCP连接建立的时间（需要1个RTT）。至少有如下2种方法能判断TCP连接已经建立：
>
> 图(b)最后一行的ASCII部分，出现了 tml HTTP /1.1..Ac，说明这是一个携带完整HTTP请求的报文。只要以太网帧中携带了应用层数据（例如：HTTP、FTP等），就说明TCP连接已经建立完成。
>
> ◇ 分析图 (b) 的十六进制数据区，依次是以太网帧首部（14B）、IP 分组首部（20B）、TCP 首部。TCP 首部报文段格式如下图所示，TCP 首部的第 13B 以后的连续 12 位是保留字段和控制位，即  $018H = 0000\ 0001\ 10\ 0\ 0$，可知 SYN = 0，则说明 TCP 连接已建立。
>
> ②仅在 TCP 连接建立阶段，主动发起连接（第1次握手）和被动响应连接（第2次握手）这两个报文中，SYN = 1。后续任何阶段 SYN 均为 0（第3次握手阶段也是）。
>
> (4) 路由器 R 转发 IP 分组时，需要修改 IP 分组首部中的字段有：
>
> ◇ 生存时间（TTL）：每经过一个路由器，TTL 减 1。
>
> ☐ 头部校验和：因为 TTL 改变，需要重新计算 IP 分组首部校验和。
>
> ◇ 源 IP 地址：NAT 场景下，私有 IP 地址 10.2.128.100 会被转换为路由器 R 的公网 IP 地址 101.12.123.15。
>
> 【提示】若 IP 分组超过链路 MTU（1500B），则需要分片，就会导致总长度、标志位、开端移字段会被修改。在本题中 Web 请求的 IP 分组总长度为 01efH=495<1500，故无需分片。▷【点评】难题。 $^{①}$ 本题综合性强，对跨考生非常不友好。图 (b) 中 hexdump 格式数据，若此前没见过，很可能无从下手。但这些在 408 考试中作为常识性的内容出现。建议考生自己动手，用 Wireshark 做网络抓包实验，亲自体验下。
>
> ②在竟成《计算机网络考研复习全书》附录3中，列举了一些计网的常识性实验（包含Wireshark 网络抓包等），帮助大家对抽象的协议、名词概念，有具体的认识。
>
> ③本题第(1)需要分析十六进制数据格式，难度大；第(3)问有陷阱，容易将TCP建立的1个RTT算进去，从而误算成7个RTT。但第(2)、(4)问是简单的概念题，容易猜出来。故本题还是比较容易得一半分的。
>
