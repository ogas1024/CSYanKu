## 题干

下表给出了整型信号量 $S$ 的 `wait()` 和 `signal()` 操作的功能描述，以及采用开/关中断指令实现信号量操作互斥的两种方法。

功能描述：

```c
Semaphore S;
wait(S) {
    while(S<=0);
    S=S-1;
}
signal(S) {
    S=S+1;
}
```

方法 1：

```text
Semaphore S;
wait(S) {
    关中断;
    while(S<=0);
    S=S-1;
    开中断;
}
signal(S) {
    关中断;
    S=S+1;
    开中断;
}
```

方法 2：

```text
Semaphore S;
wait(S) {
    关中断;
    while(S<=0) {
        开中断;
        关中断;
    }
    S=S-1;
    开中断;
}
signal(S) {
    关中断;
    S=S+1;
    开中断;
}
```

请回答下列问题。

- **（1）** 为什么在 `wait()` 和 `signal()` 操作中对信号量 $S$ 的访问必须互斥执行？
- **（2）** 分别说明方法 1 和方法 2 是否正确。

若不正确，请说明理由。
- **（3）** 用户程序能否使用开/关中断指令实现临界区互斥？为什么？

> [!note]- 原题截图
> ![[王道OS-2.3综-025.png]]

> [!success]- 答案与解析
> **答案：**
>
> 1. wait和signal对共享信号量S的访问必须互斥。方法1错误：当S≤0时在关中断状态进入while死循环，其他进程无法修改S；方法2在循环中重新开中断，使其他进程可修改S，因而正确。
>
> 2. 用户程序不能用开/关中断实现互斥，因为这两条都是只能在内核态执行的特权指令。
>
> **解析：** 软件忙等实现必须允许持有资源者继续运行并改变条件；关中断范围过大会让等待条件永远无法改变。
